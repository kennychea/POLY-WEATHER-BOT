# P5.3.1 — Session-level L1 cache for ensemble fetches

You are working on a Polymarket weather arbitrage bot. Read `tasks/lessons.md` first. Read `.planning/phases/phase-5/PLAN.md` section P5.3.1 for full details.

## Task
Add an in-memory session-level cache (L1) for ensemble forecasts to avoid redundant Open-Meteo API calls within a single scan cycle. The existing file cache (30min TTL) stays as L2.

## Files to modify
- `weather/ensemble.py` — add session_cache param to fetch_ensemble_result(), add cache stats
- `main.py` — create session_cache dict per scan cycle, pass to _evaluate_market()
- `tests/test_ensemble.py` — add 4 new tests

## Steps
1. Read `weather/ensemble.py` and `main.py` to understand current flow
2. Add `session_cache: dict | None = None` param to `fetch_ensemble_result()`
3. Cache key: `f"{city}_{target_date}_{metric}_{unit}"` (includes metric!)
4. Check L1 cache before L2 file cache
5. Store result in L1 after fetch
6. Add `_cache_stats` dict and `get_cache_stats()` function for monitoring
7. In `main.py:scan_and_trade()`, create `session_cache = {}` at start of cycle
8. Pass session_cache through to `_evaluate_market()` and then to `fetch_ensemble_result()`
9. Log cache stats at end of scan cycle
10. Write tests: L1 hit, different city miss, None disables L1, stats increment
11. Run `python -m pytest tests/test_ensemble.py -v` — all pass
12. Run `python -m pytest tests/ -v` — 0 regressions

## Constraints
- Don't break existing file cache (L2)
- session_cache=None must work (backward compat)
- Cache key MUST include metric dimension to avoid collisions

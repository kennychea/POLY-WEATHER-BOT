# P5.5.1 — Telegram alerts: edge, resolution, daily summary

You are working on a Polymarket weather arbitrage bot. Read `tasks/lessons.md` first. Read `.planning/phases/phase-5/PLAN.md` section P5.5.1 for full details.

## Task
Add structured Telegram alert methods for edge discovery, trade resolution, and daily summary at midnight UTC.

## Files to modify
- `infra/telegram.py` — add alert_edge(), alert_resolution(), alert_daily_summary()
- `main.py` — wire edge alert in _evaluate_market(), add _daily_summary_loop()
- `tests/test_telegram.py` — add 7 new tests

## Steps
1. Read `infra/telegram.py` and `main.py` to understand current Telegram integration
2. Add `import html` to telegram.py if not present
3. Add `alert_edge(signal_type, edge, net_edge, market_question, location, price)` method
4. Add `alert_resolution(market_question, signal_type, entry_price, exit_price, pnl, win, resolution_source)` method
5. Add `alert_daily_summary(trades_opened, trades_resolved, total_pnl, win_rate, bankroll)` method
6. All methods must gracefully no-op if Telegram is not configured (check self._enabled)
7. In main.py _evaluate_market(): call telegram.alert_edge() after opening a trade
8. In main.py: add _daily_summary_loop() that calculates next midnight UTC and sleeps until then
9. Register _daily_summary_loop in main() tasks list
10. Write tests for all 3 alert methods (enabled + disabled states)
11. Run `python -m pytest tests/test_telegram.py -v` — all pass
12. Run `python -m pytest tests/ -v` — 0 regressions

## Constraints
- Use HTML parse_mode (existing pattern)
- All methods must be no-op when Telegram disabled (no credentials)
- Daily summary uses midnight UTC calculation, not flat 86400s sleep
- Truncate market_question to 80 chars in alerts

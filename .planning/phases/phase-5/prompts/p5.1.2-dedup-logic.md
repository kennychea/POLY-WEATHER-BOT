# P5.1.2 — Dedup logic in scan loop

You are working on a Polymarket weather arbitrage bot. Read `tasks/lessons.md` first. Read `.planning/phases/phase-5/PLAN.md` section P5.1.2 for full details.

## Prerequisites
P5.1.1 must be done first (traded_positions table in db.py).

## Task
Add in-memory dedup set to prevent re-opening positions for the same (market_id, signal_type) pair. Hydrate from DB on restart for persistence.

## Files to modify
- `main.py` — add _TradeDedup class, wire into scan_and_trade() and _evaluate_market()
- `simulator/paper_trader.py` — pass dedup to constructor, call dedup.remove() on resolution
- `tests/test_dedup.py` (new) — 4 new tests

## Steps
1. Read `main.py` and `simulator/paper_trader.py` to understand current flow
2. Create `_TradeDedup` class in main.py with: is_active(), add(), remove(), hydrate(db)
3. In build_components(), create dedup instance
4. In main(), call `dedup.hydrate(db)` after `db.init_db()`
5. Pass dedup to scan_and_trade() and _evaluate_market()
6. In _evaluate_market(), after computing edge: check `dedup.is_active()`, skip if True
7. After open_trade() succeeds: call `dedup.add()` + persist to DB
8. Pass dedup to WeatherPaperTrader constructor
9. In _resolve_trade() and _force_resolve(): call `dedup.remove()` + `db.mark_position_resolved()`
10. Write tests: blocks duplicate, allows different direction, remove allows reopen, hydrate from DB
11. Run `python -m pytest tests/test_dedup.py tests/test_db.py -v` — all pass
12. Run `python -m pytest tests/ -v` — 0 regressions

## Constraints
- Dedup key is (market_id, signal_type) — one position per market per direction
- Must survive restarts via DB hydration
- dedup.remove() MUST be called in both _resolve_trade() and _force_resolve()

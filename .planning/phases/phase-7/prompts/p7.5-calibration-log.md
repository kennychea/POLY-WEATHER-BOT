# P7.5 — Historical Calibration Tracking

## Objective
Log every forecast + outcome to a DB table for computing per-model Brier scores. Foundation for auto-tuning model weights in a future phase.

## Changes

### infra/db.py
1. Add `forecast_log` table to schema:
   ```sql
   CREATE TABLE IF NOT EXISTS forecast_log (
       id INTEGER PRIMARY KEY AUTOINCREMENT,
       city TEXT NOT NULL,
       target_date TEXT NOT NULL,
       metric TEXT NOT NULL,          -- "temp_high", "temp_low", "precip"
       model TEXT NOT NULL,           -- "gfs_seamless", "ecmwf_ifs025", etc.
       member_count INTEGER,
       probability REAL NOT NULL,     -- model's predicted P(event)
       actual_outcome INTEGER,        -- 1 = event happened, 0 = not, NULL = pending
       brier_score REAL,              -- (prob - actual)^2, filled on resolution
       market_id TEXT,
       logged_at TEXT NOT NULL
   );
   ```
2. Add `log_forecast()` method to DbWriter
3. Add `update_forecast_outcome()` — called when trade resolves
4. Add `get_brier_scores(model=None)` — aggregate Brier scores

### weather/calibration.py (new file)
1. `log_forecast(db, city, date, metric, model, member_count, prob, market_id)` — convenience wrapper
2. `resolve_forecast(db, market_id, actual_outcome)` — compute and store Brier score
3. `brier_report(db) -> dict[str, float]` — per-model average Brier scores
4. CLI: `python -m weather.calibration --report`

### main.py
1. After calculating probability in `_evaluate_market()`: call `log_forecast()`
2. No behavioral change — pure logging

### simulator/paper_trader.py
1. On trade resolution: call `resolve_forecast()` with actual outcome

## Brier Score Reference
- `brier = (predicted_prob - actual_outcome)^2`
- Lower = better. Perfect = 0.0, worst = 1.0
- Climatology baseline for binary weather events: ~0.25
